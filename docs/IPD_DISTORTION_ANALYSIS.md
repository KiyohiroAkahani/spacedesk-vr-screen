# IPD シフトと曲面感の数理分析（課題 A / B）

2026-06-10, Claude Fable 5。シミュレーションコードは Python（使い捨て、
手法は本文に記載）。モデル: `SbsRenderer` の実シェーダー
`f = 1 + k1·r² + k2·r⁴`, `du = lensCenter + c·f`、K1=0.22 / K2=0.10、
画面= 150mm 幅スマホ（半眼 75mm = u 1.0）、レンズ間隔 = IPD ≈ 63mm。

## 前提となる幾何

レンズ光軸は各眼ハーフ中心から **6mm（u=0.08）内側（seam 寄り）**。
だから IpdShift ≈ +8% で「コンテンツ中心 = レンズ中心」が成立する。
1% ステップ = 片眼 0.75mm = **左右像間隔 1.5mm/押**。

## 課題 B「曲面が平面になった」— 機構を特定

**結論: ユーザーの体感は正しい。K1/K2 は不変でも、視線位置の歪み構造が
変わった。**

- IpdShift=0 時代: 歪み中心はコンテンツ中心 (u=0.5)、しかし視線（レンズ
  光軸）は u=0.58。つまり**ユーザーは歪みの「軸外」を見ていた**。
- 軸外では垂直線が湾曲する（円柱スクリーン的キュー）。視線直下の垂直線の
  弓なり量（±0.35v 範囲のサジッタ）:

  | 垂直線の位置（視線から） | 旧 (中心ズレ8%) | 新 (中心=視線) |
  |---|---|---|
  | 視線上 (0)   | **0.16mm** | **0.00mm（構造的にゼロ）** |
  | +0.1 (seam側) | 0.35mm | 0.20mm |
  | −0.1 (耳側)   | 0.04mm | 0.20mm |
  | +0.2 (seam側) | 0.53mm | 0.39mm |

- つまり旧状態では「視線のド真ん中＋seam 側（=両眼視野が重なる領域）」で
  垂直線が強く湾曲していた。IpdShift 後は視線上の湾曲が**厳密に 0**になり
  （中心を通る線は歪みで曲がらない）、強かった seam 側も半減。
  → **「中央が平面化した」体感と定量的に一致**。
- 水平線の弓なり量は前後で**不変**（中心の水平移動は水平線のサジッタを
  変えない。数値確認済み 1.00x）。「縦線だけ平らになった」のが正体。
- 視線中心の f' 由来の局所異方性も 0.28% → 0% に消失（副次的）。

### 含意

- 中心対称な radial モデルで「視線上の縦線湾曲」は**原理的に復元不可能**
  （中心を通る線は常に直線）。復元したければ (a) 中心を再びズラす =
  ピント問題の再発（却下）、(b) **K1/K2 を引き上げ周辺の湾曲を増やす**
  （視線±0.1〜0.2 の縦線が 0.20→0.3mm 級になる）、(c) 円柱項
  （`du.x += kc·c.y²·c.x` 型）の追加実装（将来案）。
- まず (b) をライブ調整できるようにし、実機の体感で最適値を探すのが合理的
  → `Ctrl+Alt+Shift+B/N` 実装（×1.10 / ÷1.10、config.json に自動保存）。
- 参考値: 旧 seam 側湾曲 0.35mm を中心整列のまま再現するには K1≈0.38 相当
  （×1.75）。ただし四隅の圧縮は f(0.5)=1.135 → 1.24 に増える。まず
  K1=0.26〜0.33（B を 2〜4 回）から試すこと。
- もう一つの要因 = **輻輳**。IpdShift を入れ過ぎると（像間隔 < IPD）両眼が
  寄り眼になり「画面が近い・小さい・平面」と知覚される（「重なりすぎる」
  報告と整合）。8% は幾何学的整列（無限遠相当）。**最適は「融像が安定する
  最小シフト」**で、6〜8% 帯を 0.5% 刻みで探るべき。

## 課題 A「両眼同時にピントが合わない」— 仮説の序列

1% = 1.5mm はスイートスポット近傍では粗すぎる。さらに水平シフトだけでは
直せない誤差が 2 つある:

1. **上下の眼間差（最有力）**: 垂直融像余力は ±0.3〜0.5° しかない。
   レンズ高の個体差・スマホの傾きで左右像に 0.2〜0.35mm の高低差が出る
   だけで「片眼ずつなら合うが両眼だと崩れる」symptom が出る。水平 IPD を
   いくら振っても直らない。→ `EyeYDiff`（U/O、0.25%/押 = 0.16mm = 0.23°）。
2. **スマホの左右置きズレ**: トレイ内でスマホが横に 2〜3mm ズレていると
   左右で必要シフト量が非対称になり、対称 IpdShift では両眼同時に合わない。
   → 共通オフセット `OffsetX`（J/L）。`IpdShift（対称）+ OffsetX（共通）` で
   左右独立シフトと同じ自由度を、物理的に意味のある 2 ノブで張る。
3. **ステップが粗い**: → 矢印を 0.5%/押（0.75mm/押）に変更。
4. **目標物がない**: デスクトップ画面では融像誤差を判別しにくい。
   → テストパターン（T）: 中央十字＋ドット（融像ターゲット）、同心円と
   グリッド（曲率・歪み確認）、外周枠（シフトの食われ＝クランプ検出）。

## キャリブレーション手順（実機、この順で）

1. `T` でパターン表示（縮尺は 70〜80% のまま）。
2. **片眼ずつ交互に閉じる**: 十字の高さが左右で違う → `U`/`O` で一致させる。
3. 両眼で見る: 十字が左右に二重 → `→`（narrower）を 1 押しずつ。一重に
   なったら止める（押し過ぎ＝「重なりすぎ/近すぎ」感）。
4. 十字が画面中央からズレている（頭をまっすぐにして）→ `J`/`L`、`I`/`K`。
5. 曲面感: グリッド縦線の湾曲を見ながら `B` で好みまで増やす。
6. 値は config.json に自動保存。`[INFO]` ログの数値を記録して報告。

## 既知の注意

- ContentScale=100% だと Fit 矩形がハーフ幅いっぱいになり、水平シフトは
  クランプで効かない（70〜80% 運用なら余白あり）。本修正でレンズ中心は
  「クランプ後の実シフト」に追従するようにした（旧実装はクランプ時に
  コンテンツ中心と歪み中心が分離するバグがあった）。
- 本分析の mm 値は 150mm 幅/65mm 高の表示域を仮定した目安。実機のスマホ
  寸法で線形にスケールする。
